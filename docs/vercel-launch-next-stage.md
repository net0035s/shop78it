## ลำดับงานที่เหลือ

1. เก็บสำรองและกุญแจ archive อีกชุดนอกเครื่อง แยกที่เก็บกุญแจจาก archive สำรองรอบนี้ครอบคลุมเฉพาะตารางธุรกิจ public ไม่ใช่ Supabase Auth/Storage หรือ configuration ของ Vercel/Clerk
2. ตรวจแผน commerce-migration-plan.md และ encryption-key-rotation.md รวมการจัดการ 24 ค่าที่เปิดไม่ได้ การแทนค่าด้วย MOCK ไม่ใช่การกู้ข้อมูลเดิม ต้องยืนยันนโยบายข้อมูลทดลองก่อนลงมือกับต้นทาง
3. ก่อนเปลี่ยนจริงต้องมีวิธีหยุดการเขียนจากเว็บหลักเดิมที่ตรวจแล้ว สำรอง configuration/กุญแจสินค้าเดิมอย่างปลอดภัย และตรวจข้อมูล/backup ใหม่อีกครั้งหากมีออเดอร์หรือข้อมูลเปลี่ยน ห้ามอาศัย flag ที่โค้ดเวอร์ชันเก่าไม่รองรับเพื่ออ้างว่าหยุดรับออเดอร์แล้ว
4. ดำเนิน commerce migration และกุญแจเป็นคนละขั้นภายใต้แผนที่อนุมัติ พร้อมตรวจข้อมูลก่อน commit และ rollback ทั้งฐานกับ runtime เป็นคู่เดิม ไม่ใช้สคริปต์ rehearsal เขียนฐานจริง
5. ตั้งและตรวจอีเมล/Telegram/worker และ Clerk บน deployment ที่จะเปิดจริง; ตรวจบัญชีและ Webhook Stripe Live กับ TrueMoney ตามสิทธิ์ที่ได้รับ ยังไม่รับเงินจริงขณะเตรียม
6. Vercel ปัจจุบัน Hobby ต้องจัดแผนสำหรับการใช้เชิงพาณิชย์และ worker ทุก 5 นาที รวมแก้ quality gate ที่ยังค้างก่อนเปิด ต้องแจ้งค่าใช้จ่ายก่อนให้เจ้าของซื้อ
7. เตรียม Production โดยยังปิดรับเงินจริงและตรวจระบบก่อน เมื่อถึงช่วงท้ายจึงซื้อ/ผูกโดเมนตามที่เจ้าของเลือก ตรวจ URL/DNS ของ Clerk/Stripe/อีเมล/redirect ให้ตรงกับโดเมนสุดท้าย การตรวจส่วนที่ขึ้นกับโดเมนทำได้หลังผูกโดเมนแล้ว จากนั้นจึงอนุมัติเปิดให้ลูกค้าและรับเงินจริงเป็นขั้นสุดท้าย

ข้อที่ยังไม่ได้ทำ: ไม่มี migration/rekey ต้นทาง ไม่มี Production deploy ไม่มีการเปิด Live payments ไม่มีการซื้อ Vercel/โดเมน และยังไม่ยืนยันสำรองนอกเครื่อง

## หลังเจ้าของอนุมัติให้ดำเนินการ — 12 ต.ค. 2026 เวลา 12:28 น.

- lint/typecheck, `npm test` และ sandbox production build ผ่าน ตรวจ SMTP authentication และ Telegram token แบบไม่ส่งข้อความผ่าน; Clerk ที่ตรวจเป็น test instance มีแอดมิน primary email ยืนยันแล้ว 1 คน ผลนี้ไม่ใช่การยืนยัน Clerk Live หรือ email/Telegram delivery ของเว็บหลัก
