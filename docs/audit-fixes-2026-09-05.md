# ผลแก้ไข 26 ประเด็น — 5 กันยายน 2026

แก้โค้ดตามรายงานครบ 26 ประเด็น โดยเริ่มจากการเข้าถึงข้อมูล การรับเงิน และสต็อก ก่อนต่อหน้าลูกค้า หลังบ้าน และการตรวจคุณภาพ

สถานะนี้หมายถึงการแก้ไขและทดสอบใน workspace/sandbox ไม่ใช่การเปิดใช้งานจริง ฐานข้อมูลจริงยังไม่ถูก migrate, กุญแจจริงไม่เปลี่ยน, ไม่รับเงินจริง และไม่ deploy งานและข้อมูลเดิมที่แก้ค้างไว้ยังอยู่

## การทดสอบที่ทำแล้ว

- ชุดธุรกรรมร้านค้า 28 กลุ่มผ่านใน PostgreSQL จำลอง PGlite ผ่าน Prisma โดยเรียก application logic และ API handlers จริง
- ชุด import/key configuration ผ่าน: import ได้แม้ไม่มี key แต่งานข้อมูลลับยังปฏิเสธ
- ชุดทดสอบกุญแจเดิมผ่านด้วยค่าจำลอง ไม่มีการพิมพ์ข้อมูลลับ
- ชุด migration ผ่านด้วยฐานข้อมูลจำลองที่มี schema เก่าและข้อมูลตัวอย่าง ก่อนใช้ additive migration
- ESLint ผ่านโดยกำหนด warnings เป็นศูนย์ และ TypeScript ผ่าน
- Next production build ผ่านใน environment จำลอง (สร้างไฟล์เท่านั้น ไม่ deploy)
- npm audit ครั้งสุดท้าย: 0 vulnerabilities
- เบราว์เซอร์: หน้าแรกมีสินค้า manual และสินค้าหมด พร้อมสตางค์; ยืนยันลิงก์ออเดอร์ได้; เปิดชำระบิลเดิมด้วยยอดและเวลาหมดอายุเดิม

คำเตือน EMAIL/Telegram missing ที่ปรากฏในชุดทดสอบเป็นค่าที่ตั้งให้ว่างโดยเจตนาเพื่อไม่ส่งข้อความจริง และใช้ตรวจว่าคิวบันทึก failed อย่างถูกต้อง

PGlite ใช้เครื่องยนต์ PostgreSQL แบบหนึ่ง connection จึงตรวจคำขอพร้อมกันในระดับแอปได้ แต่ไม่ทดแทนการทดสอบ lock/contention บน PostgreSQL server หลาย connection ชุด CI สำหรับ PostgreSQL 16 พร้อมแล้ว แต่ยังไม่ได้ push หรือรัน CI บนบริการภายนอก

## สิ่งที่ยังต้องดำเนินการก่อนเปิดระบบจริง

1. สำรองและทดลอง restore ข้อมูลจริง ตรวจ schema drift และอนุมัติแผนใน commerce-migration-plan.md
2. ตรวจและอนุมัติแผนกุญแจเดิมก่อนเปลี่ยน ENCRYPTION_KEY พร้อมทดลองถอดรหัสในสำเนาข้อมูล
3. ทดสอบ Clerk สำหรับแอดมินด้วย instance ทดสอบ และทดสอบสัญญา API ของช่องทางรับเงินที่ได้รับอนุญาต คำตอบผู้ให้บริการในงานนี้เป็น mocks ทั้งหมด
4. ตรวจ SMTP/Telegram/cron บนสภาพแวดล้อมทดสอบที่ตั้งค่าแล้ว รวมกรณีคิวหมดจำนวน retry
5. กระทบยอดออเดอร์เดิมที่มีคีย์ sold แต่ยัง pending รวมทั้งวันรับเงินเก่าที่เป็นค่าประมาณ
6. ทดสอบ CI หลาย connection ก่อนงานเปิดรับเงินจริง โค้ดระบบยังเริ่มต้นปิดรับเงิน

สิ่งเหล่านี้เป็นข้อจำกัดการเปิดใช้งานจริงที่ยังไม่ได้ดำเนินการตามขอบเขตผู้ใช้ ไม่ได้ถือว่าการผ่าน sandbox เป็นการอนุมัติให้ deploy
