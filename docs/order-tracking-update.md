# ติดตามสถานะออเดอร์และรายละเอียดบิล — 12 ตุลาคม 2026

ตรวจฐาน Sandbox แบบอ่านอย่างเดียวหลังเจ้าของจัดส่ง Manual: ออเดอร์ Stripe ทั้ง 3 รายการบันทึก completed แล้ว ไม่แก้หรือลบออเดอร์ของเจ้าของ

หลังบ้านบันทึก status และข้อความส่งมอบใน transaction อยู่แล้ว หน้ารับสินค้าตรวจใหม่ทุก 10 วินาที ส่วนหน้าติดตามเดิมตรวจเฉพาะค้นหา/กดอัปเดต จึงเพิ่มการตรวจทุก 10 วินาทีขณะหน้าเปิดอยู่ และตรวจเมื่อกลับมาโฟกัสแท็บ ป้องกันคำตอบการค้นก่อนหน้าทับคำตอบล่าสุด

เพิ่ม POST /api/orders/track: ใช้เลขออเดอร์และอีเมลที่ตรงกันคืนเฉพาะเลขบิล สถานะ ยอด วันเวลา และชื่อ/จำนวน/ราคาสินค้า ไม่มีการส่งเมล ไม่มี Set-Cookie หรือสิทธิ์รับสินค้า และไม่อ่านหรือถอดรหัส DeliveryItem/deliveredContent เลือกเฉพาะฟิลด์ที่จำเป็นจากฐานโดยตรง ตรวจ origin, ขนาด JSON, rate limit และ private/no-store อีเมลผิดและเลขบิลไม่พบตอบข้อความเดียวกัน

คีย์สินค้า รหัสผ่าน และข้อความจัดส่งยังต้องใช้ cookie จากการซื้อหรือจากลิงก์ยืนยันอีเมล การรู้ที่อยู่อีเมลเพียงอย่างเดียวไม่ใช่หลักฐานควบคุมกล่องเมล API เดิมยังไม่อนุญาตให้เปิดข้อมูลส่งมอบด้วยเลขบิลเพียงอย่างเดียว

แก้ API ขอ access link เมื่อปิด SMTP: แจ้งว่ายังไม่พร้อมส่งเมลแทนตอบว่าจะส่งลิงก์แล้วสร้างคิวที่ส่งไม่ได้ หน้า Preview แสดงว่าปิดการส่งเมล ส่วนการค้นสถานะ/รายละเอียดบิลยังใช้ได้ การแลกลิงก์ยืนยันที่ออกแล้วไม่ต้องพึ่ง SMTP และยังใช้ครั้งเดียว

Browser E2E ผ่าน 14 กลุ่มในฐานชั่วคราวและ SMTP sink รวมแอดมินจัดส่งแล้วหน้าติดตามกับหน้ารับสินค้าที่เปิดค้างอัปเดตโดยไม่ reload; เลขกับอีเมลแสดงบิลโดยไม่มีเมลหรือสิทธิ์รับสินค้า; กรอกผิด/foreign origin ถูกปฏิเสธ; การยืนยันลิงก์เดิมและซื้อซ้ำยังผ่าน TypeScript และ lint ผ่าน รายงาน launch-storefront-e2e-latest.json

อัปเฉพาะ Preview Sandbox ไม่เปลี่ยน Production และไม่เปิดรับเงินจริง ผลตรวจออนไลน์รวม metadata lookup และ SMTP-disabled ดู launch-preview-smoke-latest.json ส่วน Webhook เดิมดู launch-stripe-webhook-online-latest.json
